# Doubt journal

An academic journal with one reviewer. Every paper I read gets a folder, a public review, a
rating, and — if I bothered to rebuild it — the notebooks I wrote to understand it.

It is also a game. Reading carelessly scores 1; rebuilding a paper from scratch scores 8. The
scoreboard is computed from the reviews themselves, so the only way to move a number is to
actually read something.

- **Papers** — <https://act65.github.io/doubt-journal/papers/>
- **Scoreboard** — <https://act65.github.io/doubt-journal/stats/>

## Layout

```
_papers/<slug>/index.md     the review — front matter is the metadata, body is the prose
_papers/<slug>/*.py         marimo notebooks that rebuild the idea in JAX
_data/tags.yml              tag vocabulary: label + kind (topic / archetype / meta)
_data/backlog.yml           the reading queue — NOT published; used by the scorer and --from-backlog
_data/gamify.yml            the rules: XP per depth, rank thresholds, annual target
_data/stats.yml             GENERATED by scripts/score.py — committed so XP shows up in the diff
tags/<slug>.md              GENERATED stub pages, one per tag in use
_posts/                     the older reviews, from before papers had folders
```

There are no nested folders. Grouping is done with **tags**, so a paper can sit under
`probabilistic-methods` and `hidden-equivalence` at once, and `/papers/` filters on any
combination of them.

## Adding a paper

```sh
python scripts/new_paper.py bfn --title "Bayesian Flow Networks" \
    --ref https://arxiv.org/abs/2308.07037 --authors "Graves et al." --year 2023 \
    --depth read --tags probabilistic-methods,generative-models

# or pull the metadata off the backlog:
python scripts/new_paper.py neural-collapse --from-backlog "neural collapse"
```

Then write the review, set `rating:` when you've decided, and rescore:

```sh
python scripts/score.py
```

Which prints the damage:

```
  2 papers · 16 XP · Desk Clerk
  9 XP to Reviewer 2 (64%)
  2/52 in 2026 (27.6 behind pace)
  streak 1 week (best 1)
```

Commit `_data/stats.yml` along with the review — the diff is the scoreboard's history.

## Mining old conversations

Papers you explored with Claude but never wrote up are recoverable — the transcripts are on disk.

```sh
python scripts/mine_conversations.py --fetch-metadata      # rank what you actually engaged with
python scripts/mine_conversations.py --draft arxiv:2603.27270   # scaffold a draft review
```

Each mention is weighted by where it appeared (something you typed counts far more than a hit
inside a tool result) and **divided by how many papers shared that message**, so a reading list
of thirty doesn't register as thirty papers you studied. Depth is guessed from focused mentions
plus nearby code edits; `extended` is never inferred, and no Review is ever written for you.

Drafts land with `draft: true` / `published: false` — invisible to the site and the scoreboard
until you promote them. The report lives in `.mined/`, gitignored, because it quotes private
conversations into a public repo.

## How a review is laid out

Every review follows the same five sections, so they're comparable and so an old one is still
navigable years later:

| section | | |
|---|---|---|
| `## Review` | required | The verdict. What's the contribution, and does the paper demonstrate it? |
| `## Problem` | required | What's being solved, why it's hard, and the notation. |
| `## Overview` | required | The paper in my own words — the tutorial I wish I'd been handed. |
| `## Additional thoughts` | optional | My ideas, extensions, and open questions. |
| `## Feedback` | optional | What the authors should have done. |

`scripts/score.py` warns about reviews missing a required section, still carrying a placeholder
verdict, or claiming `depth: rebuilt` with no notebook to show for it.

## Scoring

`depth` is the honest bit. It records how hard you actually looked, not how long the review is.

| depth | XP | means |
|---|---|---|
| `skim` | 1 | read the abstract and figures |
| `read` | 3 | read it properly, could summarise the argument |
| `rebuilt` | 8 | reimplemented the core idea; there is a notebook |
| `extended` | 15 | went past the paper — a new experiment, a case it gets wrong |

`rating` is out of 10 and drives the verdict: at or above 5 the paper is **accepted**, below it
is **rejected**, and no rating at all means **under review**. Blank is not zero — a paper you
haven't judged yet is different from one you thought was worthless.

Ranks run Desk Clerk → Reviewer 2 → Reviewer → Area Chair → Senior AC → Program Chair →
Editor-in-Chief. Badges, streaks and backlog coverage are all configured in `_data/gamify.yml`;
edit the thresholds there rather than in the script.

## Notebooks

```sh
uv run marimo edit _papers/bfn/bfn_simple.py     # interactive
uv run marimo run  _papers/bfn/bfn_simple.py     # read-only app view
```

`uv` resolves the environment from `pyproject.toml` / `uv.lock` on first run. The notebooks pin
`JAX_PLATFORMS=cpu` and enable float64 themselves, so they run anywhere. They are linked from
each paper page but not served by the site — GitHub renders them fine.

## Building the site

```sh
bundle install
bundle exec jekyll serve
```

Pushes to `master` build and deploy through `.github/workflows/pages.yml`. The workflow runs
`score.py --check` first, so a review committed without a rescore fails the build rather than
quietly publishing stale numbers. It cannot use the stock GitHub Pages build because the site
uses `jekyll-scholar` and a `_plugins/` file, both of which that build ignores.

## Conventions

- **One folder per paper**, slug short and lowercase (`bfn`, `enn`) — it's what you type to open
  the notebook.
- **Notebooks are marimo `.py` files**, not `.ipynb` — they diff cleanly in git.
- **Notebook names describe the angle**, not the paper: `epistemic_nn_from_coins.py` and
  `epistemic_nn_from_gaussian.py` are two routes to the same idea. Several small notebooks
  attacking one paper from different directions beats one big one.
- **Build up, don't summarize.** Start from something already understood (a coin, a Gaussian)
  and climb to the paper's construction.
- **PDFs are gitignored.** Link to the paper in the front matter `ref:` instead.
